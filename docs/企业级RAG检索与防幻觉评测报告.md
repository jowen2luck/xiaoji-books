> **项目对应**：简历第一项 —— 企业级多模态知识库问答 Agent 研发与评测  
> **底层语料**：AIAE Book Evidence 引擎（真实收录 67 本专著与历史公文档案，共计 25,022 条结构化段落证据）  
> **评测环境**：本地 CPU 环境（AMD Ryzen 16-Core）+ Python 3.12（`llm3.12`）  
> **评测日期**：2026-09-13

## 一、 评测背景与业务场景定义

在企业规章制度、公文法规、合同风控与历史档案等知识库问答场景中，系统面临四类核心挑战：
1. **专有名词与条款精确检索**：如具体会议名称、发文日期、文号、特定人名。
2. **跨表述与同义词语义泛化**：提问表述与文献原文词面不重合（如“抗击帝国主义与反霸权”对应原文“反帝统一战线”；现代“修身养性”对应古文/白话“不婚不宦，情欲失半”）。
3. **复杂长句与口语化意图**：业务员工提问常带“我想了解一下当年关于...”、“具体内容是什么”等冗余修饰与停用词。
4. **越界超纲与无依据提问（OOD, Out-Of-Domain）**：员工询问知识库完全未涵盖的内容（如外部竞品财报、IT运维实操、未收录的行政审批流程）。**企业级知识库的核心底线是严禁编造**，必须具备高可靠的兜底拒答能力。

为客观量化简历中技术方案的实际价值，我们在 `book-library-skill` 现有的 25,022 条真实语料库上，搭建了**基线系统（Baseline）**与**简历标准系统（Resume Version）**两套对照架构，并执行自动化端到端对比评测。

## 二、 对照系统架构设计

```mermaid
graph TD
    subgraph Baseline ["【基线版本 Baseline】(初级 RAG 常见形态)"]
        B_Q[用户原始输入] --> B_FTS[单路 FTS5 / 词频检索]
        B_FTS --> B_TOP[机械截取 Top-5 候选]
        B_TOP --> B_OUT[强制返回 (无拒答机制，OOD 问题必产生幻觉)]
    end

    subgraph Resume ["【简历版本 Resume】(企业级两阶段双路 + 精排 + 拒答)"]
        R_Q[用户原始输入] --> R_RW[Query 改写与停用词剥离]
        R_RW --> R_DENSE[Dense 语义向量召回 (bge-small-zh-v1.5)]
        R_RW --> R_SPARSE[Sparse 精确倒排召回 (FTS5 BM25)]
        R_DENSE & R_SPARSE --> R_RRF[RRF 倒数排名融合 (k=60)]
        R_RRF --> R_POOL[Top-20 混合粗排候选池]
        R_POOL --> R_CE[Cross-Encoder 交叉全注意力精排 (bge-reranker-base)]
        R_CE --> R_GATE{最高置信度 >= 0.35?}
        R_GATE -- 否 (OOD) --> R_REJECT[安全兜底拦截：返回拒答 (防模型编造)]
        R_GATE -- 是 --> R_PROV[绑定不可变证据层物理锚点 (页码/字符/BBox)]
        R_PROV --> R_OUT[高置信度事实证据交付]
    end
```

### 1. 基线实现（Baseline）
- **Query 处理**：无改写，原样输入。
- **检索通道**：单路 SQLite FTS5 关键词匹配。
- **排序机制**：原生 BM25 词频打分，无语义重排序。
- **防幻觉与拒答机制**：**无（0%）**。无论相关度多低，强行返回 Top-5。当遇到库外未收录问题时，会将风马牛不相及的段落喂给下游大模型，100% 诱发严重幻觉。
- **证据锚点**：仅返回片断文本与简单页码，缺乏完整物理高亮数据流。

### 2. 简历版本实现（Resume Implementation）
- **Query 改写与意图规整（Query Rewriting）**：
  - 自动剥离“我想了解一下当年关于...”、“具体内容是什么”等业务口语冗余词，分别生成适合 FTS5 倒排的实体检索式与适合语义向量模型的精炼语义命题。
- **两阶段两路混合召回（Two-Stage Hybrid Dense + Sparse Retrieval）**：
  - **Sparse 路**：SQLite FTS5 倒排匹配，负责精确命中会议名、法规文号、人名与时间。
  - **Dense 路**：基于 `BAAI/bge-small-zh-v1.5`（512维向量），采用规范检索前缀指令（`为这个句子生成表示以用于相关文章检索：`），通过余弦相似度召回语义相关候选。
- **无量纲免参融合（Reciprocal Rank Fusion, RRF）**：
  - 采用标准公式 $RRF(d) = \sum_{m \in \{\text{sparse}, \text{dense}\}} \frac{1}{60 + \text{rank}_m(d)}$ 消除异构分数体系（BM25 与 Cosine）的量纲偏差，合并去重输出 Top-20 候选池。
- **交叉全注意力精排（Cross-Encoder Reranker）**：
  - 接入 `BAAI/bge-reranker-base` 模型，将 `(Query, Candidate_Document)` 拼接输入 Transformer 进行全注意力交互打分，精准剔除“字面包含同名词但语义风马牛不相及”的伪相关候选。
- **绝对置信度标定与兜底防幻觉拒答（Confidence Calibration & Abstention Guard）**：
  - 经实验标定置信度截断阈值 $\tau = 0.35$。若候选集最高分 $< \tau$，系统主动截断并输出 `is_abstained = True`，附带标准拒答理由，阻止低证据流入下游 LLM。
- **不可变证据层物理锚点追溯（Ground Truth Invariance & Physical Highlighting）**：
  - 严格遵循 AIAE 宪法，段落与物理锚点 1:1 绑定，输出包含 `book_id`、`page_index`、`char_range`（起止字符索引）、`layout_bbox`、`evidence_set_id` 的完整凭证链，为前端 PDF 原文绘制矩形高亮提供确定性支撑。

      - Q15: **0.0756** (< 0.35)

## 五、 物理锚点与“Engine Never Concludes”保真规范

在评测中，简历版本在返回事实证据时，严格遵循了 AIAE 架构规范中的“**Ground Truth / Navigation 分离**”与“**Engine Never Concludes（引擎绝不下结论）**”原则：
1. **绝不合成总结**：检索服务只客观返回带有绝对物理溯源的证据段落切片，不进行主观加工或改写，避免检索层自我脑补。
2. **物理高亮 1:1 强绑定**：每一条返回的 Evidence 都完整携带物理坐标字段：
   - `book_id`: 原始文档全局唯一哈希（如 `book-091201`）
   - `page_index`: PDF 物理页码（精准对应扫描件页码）
   - `char_range`: 该段文字在物理页中的字符起止偏移量 `[char_start, char_end]`
   - `layout_bbox`: 版面分析返回的像素级边界框坐标
   - `evidence_set_id`: 当前处理批次的不可变证据集签名（如 `es-872f745d0a45d967`）
3. **前端高亮渲染支持**：前端 PDF 视图组件在接收到这些字段后，可直接跳转到指定页码并在扫描原文上高亮画出半透明矩形框，真正做到“言之有据、字字可查”。

## 六、 性能拆解与生产环境工程演进路线

### 1. 本地 CPU 测试耗时拆解（单次平均约 7.1 秒）
- Query 改写耗时：~0.1ms
- Sparse 检索耗时：~25ms
- Dense 向量检索耗时：~15ms
- RRF 融合耗时：~0.2ms
- **Cross-Encoder 精排耗时**：~7,000ms（CPU 上对 Top-20 候选对执行 20 次深层全注意力前向推断，占总耗时 98%）

### 2. 生产环境优化演进方案（面试回答加分点）
1. **Reranker GPU 服务化与 TensorRT-LLM 批处理加速**：
   - 在生产环境基于 vLLM / Triton 部署 Reranker 服务，利用 GPU 显存并发执行 Batch 矩阵计算，20 对候选精排耗时可从 7,000ms 压缩至 **40~80ms**。
2. **动态两级截断（Two-Tier Filtering）**：
   - 经 RRF 融合后，根据 RRF 得分梯度动态截取前 8~10 个高置信候选送入 Cross-Encoder，减少 50% 以上精排计算开销。
3. **ANN 向量索引持久化与分块加载**：
   - 对全库段落预构建 FAISS IVF-PQ 或 HNSW 索引，单次语义召回耗时稳定在 **2~5ms** 内。
